# Process Pro audio locally with soft entitlements

Geekskai Audio Toolkit processes user-imported audio in a browser Web Worker with ffmpeg.wasm. Audio and filenames never reach Geekskai servers, which preserves the existing local-first privacy promise and avoids storage, queue, and per-job infrastructure cost. The server verifies Creem-derived capability entitlements and the normal UI loads Basic or Pro batch behavior only for entitled users, but this is intentionally a soft access boundary: a determined user can inspect or modify delivered client code. We accept that limitation for the paid MVP and will reconsider server processing or a licensed desktop application only if measured abuse becomes material. To control browser memory and reliability, the supported release is desktop Chrome and Edge, uses a sequential single-thread queue, limits Pro and Enterprise batches to 50 files, 200 MB per file, and 500 MB total, and treats Safari as beta.
