### 方法与边界

- 语言：`en / ar / de / fr / es / ja / ko / no / zh-cn / da`。英语 URL 无 `/en`；HTML 页面使用尾斜杠。保持现有 PDF、Morse 与 SoundCloud 语言例外。
- 公开 GET 采集，主抓取并发 3，单次最多 25 秒、最多 6 跳；网络失败、403、429、5xx 再试一次。记录首跳，不能只用跟随后最终的 200 判断目标健康。
- 主抓取使用 `GeekskaiSEOAudit/1.0`、`Accept-Language: en`，不发送用户凭据、不保存会话 Cookie。它不是经过验证的 Googlebot，不能据此宣称 Google 实际抓取表现。
- 使用 Chrome DevTools 复核德语 Fancy、日语 Cursed、博客第 2 页、分享结果页、工具目录、多语言导航及无效 VIN 页面。测试页已恢复为 `about:blank`。分享页浏览器样本曾受此前日语 Cookie 影响跳到日语版，证据保存真实最终地址；无 Cookie 的英语采集独立存在。
- 自动正文提取用于发现线索；流式渲染可能把文章内容放在初始 main 外。不能将提取正文短、SSR 未出现 H1、字数或字符串相似度直接等同于低质量、无内容或应 noindex。
- **BLOCKED / 未验证：** Google 选择的 canonical、实际索引、Search Console、排名、流量损失、Core Web Vitals、完整富结果资格。此次没有搜索引擎后台证据，也未执行全站性能测试。
- 本地没有 `.git` 可供识别，也没有 `node_modules`。未声称 Git diff、构建、类型检查或单元测试通过；用文件指纹验证本轮未改业务文件。

术语：**自引用 canonical** 指地址声明自身；**语言变体** 指同一用途的不同语言页面；**可索引候选** 指本轮观察为 200、允许抓取、未 noindex、canonical 自引用，不等于已被 Google 收录；**语言回退** 指既有 308 到英语的产品政策；**渠道一致性** 指 HTML、HTTP Link、sitemap 不发出互相矛盾的语言关系。未安装或未暴露可读取的专用 marketing/SEO skill，本次采用 Google 官方文档、已指定的 grill 流程及 Chrome DevTools 能力，不伪称使用了不存在的技能。

| --- | --- | --- |
| `3-beginner-friendly-ways-to-extract-audio-files-from-videos/` | `3d659-com-blog-review/` | 目标 200，但标题和主题不同 |
| `ai/deepseek-api-integration/` | `api/deepseek-api-integration/` | 目标 404 |
| `ai/how-predictive-ai-tools-can-identify-invisible-risks-for-businesses/` | `how-predictive-ai-tools-can-identify-invisible-risks-for-businesses/` | 目标 404 |

**位置：** [博客 metadata](/Users/channelwill/Downloads/geekskai/app/blog/[...slug]/page.tsx:54)。7 个 MDX 文件的确切路径见 JSON `blog_canonical_mappings[].source`，相对于项目根目录；当前源码不存在需要保留的跨站 canonical 解释。

**最小修复：** 只将这 7 个 MDX 的 `canonicalUrl` 更正为各自实际 200 路由，保留英语无前缀及尾斜杠。保留已有 PrimeVue 旧地址到新地址的 308；不创建反向重定向、不将其他文章批量重写、不合并两篇不同主题文章。现有 metadata 已用相同变量设置 `og:url`，应随之保持一致。

**验收：** 7 个源页面 canonical 均等于自身；canonical 目标首跳 200，且不是其他文章；PrimeVue 旧路径仍 308 到新路径，新路径不再指回旧路径；sitemap 继续列出实际新地址。[Google canonical 规则](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)支持统一这些归属信号，但此次未验证 Google 已如何处理错误声明。

### SEO-02 · P1 · 英语 hreflang 指向重定向别名 · FAIL

**证据：** [德语 Fancy Text Generator](https://geekskai.com/de/tools/fancy-text-generator/) 的 canonical 自引用，HTML 的英语 hreflang 却指向 `/en/tools/fancy-text-generator/`，首跳 307 到 `/tools/fancy-text-generator/`；浏览器 DOM 与响应 HTML 一致。另 18 个目标同样如此，共影响 190 个源页面。

**位置：** [Unicode 工具共享 metadata](/Users/channelwill/Downloads/geekskai/app/[locale]/tools/upside-down-text-generator/lib/seo.ts:25)、[VIN 品牌 metadata](/Users/channelwill/Downloads/geekskai/app/[locale]/tools/vin-decoder/[brand]/page.tsx:43)。前者影响 backwards、bubble、cursed、discord-font、fancy、instagram-bio、strikethrough、vaporwave、zalgo 共 9 个工具；后者影响 10 个品牌。

**最小修复：** 两处改用现有 [buildLanguageAlternates](/Users/channelwill/Downloads/geekskai/app/i18n/urls.ts:23)，传实际路径。让 `en` 与 `x-default` 都指向无 `/en` 的英语 canonical，其余语言指向各自最终 URL；保留既有 `/en` 导航重定向机制，不为此改全站 localePrefix。

**验收：** 190 个页面的 HTML 英语目标直接返回 200、自引用且可索引；每组语言相互引用；HTML、HTTP 与 sitemap 中同一语言的目标相同。不能把“跟随重定向后 200”当成目标已修正。依据：[Google 多语言声明](https://developers.google.com/search/docs/specialty/international/localized-versions)、[next-intl as-needed 行为](https://next-intl.dev/docs/routing/configuration#localeprefix-as-needed)。这是声明质量问题，不等于所有相关页面都未收录。

### SEO-03 · P1 · 语言声明包含不应作为可索引变体的地址 · FAIL

**证据：** PDF、Morse 英语页以及 SoundCloud 的 6 路由 × 4 语言，共 26 个直接响应页面，HTML 已按支持语言生成，而 HTTP `Link` 仍声明全部 10 语言。被排除的语言地址实际 308 到英语。另 VIN 对比页 10 个版本都声明全量 hreflang，但其中 9 个版本明确 `noindex,follow`。

**位置：** [Proxy 的 Link 处理](/Users/channelwill/Downloads/geekskai/proxy.ts:41)、[工具语言策略](/Users/channelwill/Downloads/geekskai/app/sitemap-config.ts:32)、[VIN 对比页语言及索引策略](/Users/channelwill/Downloads/geekskai/app/[locale]/tools/vin-decoder/vin-decoder-vs-vin-check/compare-seo.ts:19)。现有 Proxy 只为 pricing、audio-toolkit、about 清除自动 Link。

**最小修复：**

1. 保持 PDF/Morse 仅英语、SoundCloud 为 `en/fr/es/de` 的现有政策。在 Proxy 中对这些受限 Tools 路由清除 next-intl 自动生成的 `Link`，由已经正确的 HTML 和 sitemap 提供关系；匹配时移除语言前缀并规范路径，不误匹配同名前缀的其他路由。
2. 保持 VIN 对比页 9 个非英语版本 noindex。英语 HTML 仅声明 `en` 与 `x-default`；非英语 noindex 页移除其 hreflang 集合；该对比路由同样清除自动 HTTP Link。
3. 不全局删除 Tools 的 HTTP Link：PERM Tracker、Snow Day 共 20 个页面当前没有 HTML hreflang，但 HTTP 与 sitemap 提供有效关系。全局删除前必须另行补齐，此修复没有必要扩大到那里。

**验收：** 36 个页面不再声明会重定向或 noindex 的语言目标；54 个现有语言回退仍为 308；VIN 对比页 9 个 noindex 不变；其他完整多语言工具仍保留有效语言关系。Google 接受 HTML、HTTP 或 sitemap 方式，不要求三种全部同时存在；关键是有效、可维护的关系。[官方说明](https://developers.google.com/search/docs/specialty/international/localized-versions)

### SEO-04 · P1 · 分页 canonical 与非法页码处理 · FAIL

**证据：** [博客第 2 页](https://geekskai.com/blog/page/2/) 内容与第一页不同，却 canonical 到 `/blog/`。`/blog/page/0/`、`9999/`、`abc/` 均首跳 200；源码对空切片回退显示整个 posts，因而不能把这些请求解释为正确的空页 404。`/blog/page/1/` 也是独立 200 别名。

**位置：** [分页路由](/Users/channelwill/Downloads/geekskai/app/blog/page/[page]/page.tsx:14)、[父级 metadata](/Users/channelwill/Downloads/geekskai/app/blog/layout.tsx:40)、[空切片回退](/Users/channelwill/Downloads/geekskai/layouts/ListLayoutWithTags.tsx:77)。

**最小修复：** 在分页路由用严格正整数规则验证参数，先过滤可公开文章并计算总页数，越界/非整数调用 `notFound()`；页 1 永久重定向到 `/blog/`；页 N≥2 声明自己的 canonical、`og:url` 和含页码的 title，移除继承的错误 x-default 或设置到当前英语页。沿用每页 9 篇，不修改全站列表组件的既有回退语义；通过路由校验防止无效参数进入它。

**验收：** 页 2 与最后一页自引用且文章切片正确；页 1 为 308；`0/-1/abc/2abc/1.5/超出总页数` 返回真实 404；前后页链接指向可访问地址。Google 对分页建议各页拥有自己的 canonical：[分页最佳实践](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)。

**验收：** 10 种语言的桌面、移动导航 DOM 均直接链接 `/blog/`，点击最终 200；Tools 导航仍保留当前语言。扫描工具页站内链接后不再出现这 9 个已知 404 目标。
